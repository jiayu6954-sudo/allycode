# 产品与工程需求

## 1. 交付目标

从零构建可运行、可验证的二元结果市场产品切片。每个市场只有 `YES` 与 `NO` 两种结果；创建者建市，流动性提供者注入测试资金，交易者买卖份额，经授权预言机结算后，胜方可领取测试收益。

## 2. 必须交付

- `programs/`：Rust + Anchor 合约工程，包含账户、指令、错误、事件和整数安全计算；
- 可执行的确定性本地域模型，供没有 Solana 工具链的环境验证同一套状态规则；
- TypeScript SDK/索引 API，严格实现 `API_CONTRACT.md`；
- React + TypeScript 前端，至少含总览、市场、组合、活动、风险五个中文页面；
- 自有单元、集成、属性/不变量和安全测试；
- 架构、运行、测试、威胁模型、devnet 部署指南；
- 根目录 `npm run start:test`，一次启动 API 与 Web，不能依赖交互输入。

## 3. 核心规则

- 金额、份额、价格、费率全部使用整数最小单位，禁止浮点记账；
- `YES` 与 `NO` 的展示价格之和必须为 10,000 基点；
- 交易必须服务端计价并执行滑点保护，禁止负余额、超卖和重复扣款；
- 建市、交易、结算、领取必须幂等；同一幂等键对应不同载荷必须冲突；
- 市场关闭后不可继续交易；只能由配置的预言机结算，非法签名不能产生任何状态副作用；
- 预言机事件必须防重放；结算结果不可更改；每个胜方账户只能领取一次；
- 创建者奖励仅在累计成交量达到阈值后解锁，且不能重复发放；
- 所有状态变化发出稳定、可排序、可重放的领域事件，前端可据此同步；
- 高频只读接口需要缓存与可观测指标，写入后必须正确失效。

## 4. 安全与运行边界

- 默认 `NETWORK_MODE=local_only`；任何主网部署命令都必须是显式、人工、文档化步骤，测试启动不得连接主网；
- 不保存或输出钱包私钥、助记词、API Key；日志需脱敏；
- Anchor 代码至少防范未授权签名者、错误账户所有者、账户替换、算术溢出、重复初始化、重放、越权结算和重复领取；
- 所有外部输入必须有模式校验、上限和明确错误码；
- 不允许用固定响应、针对验收数据的分支或空壳文件骗过测试。

## 5. 完成定义

系统可由全新环境按照文档启动；自有测试通过；公开 API 合同全部实现；隐藏验收可复跑；已知限制真实记录。仅生成大量文件、界面截图或“已经完成”的文字不算交付。
