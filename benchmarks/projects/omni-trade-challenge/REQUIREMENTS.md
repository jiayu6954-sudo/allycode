# OmniTrade 产品与工程需求

## 1. 业务目标

为中小商家构建一个可以在本地或私有环境运行的交易自动化平台。系统从供应商同步商品，应用定价规则并上架；接收订单并安全预占库存；处理支付和物流回调；创建客服工单；在成交后执行通知与回访。所有关键动作必须可审计、可重试且不重复产生副作用。

## 2. 必须交付的模块

### 商品与选品

- 从外部供应商 API 同步商品；同一 SKU 更新而不是重复创建；
- 使用 ETag/If-None-Match 避免重复下载未变化目录；
- 定价规则：`salePrice = round(cost * (1 + marginPercent/100), 2)`，margin 范围 0–300；
- 商品状态 `draft/published/archived`；只有库存大于 0、价格合法的商品可发布；
- 商品查询必须有可观测缓存，写操作后正确失效。

### 订单与库存

- 下单必须携带 `Idempotency-Key`；相同 key + 相同载荷返回同一订单；相同 key + 不同载荷返回冲突；
- 创建订单时原子预占库存，库存不足不得产生半成品订单；
- 订单状态至少包含 `pending_payment/paid/fulfilling/shipped/delivered/cancelled`；非法状态迁移必须拒绝；
- 金额由服务端根据商品快照计算，不能相信客户端总价。

### 支付、物流和 Webhook

- 支付与物流回调使用原始请求体做 HMAC-SHA256 验证；
- Webhook 事件 ID 必须幂等，重复事件返回成功但不能重复扣库存、重复通知或重复状态迁移；
- 无效签名返回 401/403，不能改变任何业务状态；
- 支付后产生履约作业；送达后产生回访作业。

### 外部网络调用

- 所有外部调用设置超时；对 429、502、503、504 和网络错误做有上限的指数退避；
- 不重试普通 4xx；重试次数和最终失败进入指标与审计；
- `/api/admin/external-probe` 调用模拟不稳定服务，必须在前两次 503 后恢复；
- API key 只能从环境读取，不得返回前端或写入日志。

### 钩子、作业和审计

- 支持并记录 `after_catalog_sync`、`after_product_published`、`after_order_paid`、`on_low_stock`、`after_shipment_delivered`；
- 钩子失败必须被隔离和记录，不能回滚已经提交的核心交易；
- 使用可恢复作业/Outbox 语义，重复执行 worker 不得重复发送通知；
- 审计记录包含时间、事件、实体类型/ID、结果和关联 ID，不包含密钥或完整支付载荷。

### 客服与回访

- 创建客服工单并关联订单；优先级为 `low/normal/high/urgent`；
- 订单送达后运行作业，调用通知服务发送一次回访问卷；
- 重复运行作业不能重复通知。

### 管理前端

- 简洁中文界面，白底黑字、信息层级清晰；
- 页面：运营总览、商品、订单、客服、自动化；
- 展示加载、空数据、网络错误和重试状态；
- 商品可发布，订单可查看状态时间线，自动化页可查看钩子/作业/缓存/外部调用指标；
- 桌面宽屏与 1280px 窗口下可用，不出现主要内容横向溢出。

## 3. 非功能要求

- Node.js 22，Windows 本地可运行；
- 持久数据在重启后保留；并发写入不得破坏库存和幂等性；
- API 使用结构化错误：`{ "error": { "code": "...", "message": "..." } }`；
- 关键请求具有 `x-correlation-id`，缺省时服务端生成并在响应头返回；
- 日志结构化且脱敏；优雅处理 SIGINT/SIGTERM；
- 核心领域逻辑需要单元测试，网络/Webhook/缓存需要集成测试，关键路径需要端到端测试。

## 4. 不要求

- 不连接真实银行、物流、电商平台；
- 不要求 Kubernetes、云部署或多租户计费；
- 不要求生产级 PCI 认证，但代码和文档必须说明真实支付上线前的合规边界。
