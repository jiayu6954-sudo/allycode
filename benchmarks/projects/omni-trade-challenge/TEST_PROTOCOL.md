# DeepSeek V4 Flash × AllyCode 测试流程

## 测试前

1. 在“模型与 API”选择 DeepSeek、`deepseek-v4-flash`（若模型目录返回的真实 ID 不同，以供应商返回值为准）。
2. 执行 AllyCode 的五阶段连接与工具续接诊断，必须为 Agent 可用。
3. 关闭无关高占用程序，记录模型、端点、协议、思考模式、最大输出、沙箱和启用 Skills/MCP。
4. 不要把真实生产密钥写入本项目；外部模拟器只使用 `.env.example` 的测试值。

## 正式运行

1. 复制一份全新的挑战目录，目录名包含轮次，例如 `OmniTrade-Run-01`。
2. 在 AllyCode 创建一个任务并选择该目录。
3. 发送 `ALLYCODE_TASK_PROMPT.md` 全文；整个项目保持在同一任务中，不频繁新建对话。
4. 打开 Agent 检测台。允许安全读取和项目内写入；外部联网、宿主机命令和高风险操作仍按安全策略确认。
5. 不要中途人工提示怎么修；只有 Agent 明确请求无法从文件发现的业务选择时才回答。
6. Agent 宣称完成后，人工执行 `验证挑战.cmd`，不要只相信对话中的分数。
7. 导出检测台脱敏 JSON，保存 `.challenge-results/latest.json`，填写 `TEST_RECORD.md`。

## 三轮可比测试

- 每轮都从同一个干净挑战快照开始；
- 使用完全相同的模型、协议、提示词、权限和最大预算；
- 至少执行 3 轮，报告中位数，不能只展示最好的一次；
- 记录成功率、挑战分、人工 UI 评价、总时长、模型轮次、工具错误、重复工具、权限次数、输入/输出 token、cache-read token 与缓存读取比例；
- Provider 未上报缓存时标记“未观测/未上报”，不能填 0% 后下结论；
- 如果人工介入，必须记录介入次数和内容，该轮不能与零介入成绩混合。

## 建议判定

- `90–100`：本地契约基本闭环，仍需人工审查和并发/安全扩展测试；
- `70–89`：主要链路可用，但存在明显工程缺口；
- `40–69`：能构建部分系统，尚不能称为可交付；
- `<40`：复杂长任务闭环失败。

这只是 AllyCode 内部挑战等级，不等于生产认证或国际 Agent 基准。
