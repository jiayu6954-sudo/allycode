# AllyCode Agent 实时检测台

实时检测台是 Alpha.9 的本地可观测与诊断层。它读取 AllyCode 已写入 SQLite 的任务事件，按固定规则生成时间线、告警和分维度证据。检测逻辑不依赖被测模型自我评价，因此模型不能仅靠文字声称“已完成”来获得工程验证分。

Alpha.10 起，检测台读取完整的结构化事件流，不再截断前 2,000 条；原始 text/thinking/progress 分片不再逐条落库，只记录聚合摘要。模型轮次优先按 Provider usage 事件计算，TTFT 绑定到最近一次实际产生流信号的 run，重复 terminal error 按 run 归并为独立失败事件。

代码任务还会经过确定性完成门禁：项目声明的 test/build/lint/typecheck、真实浏览器 E2E 和 API 集成验收缺少成功工具证据时，任务不会被标记完成。该门禁只能证明执行证据存在，不能替代领域业务审计或人工验收。

## 本地使用

1. 启动一个任务，或从左侧历史记录进入已有任务。
2. 点击左下方“Agent 检测台”。运行中的任务每秒刷新。
3. 观察模型轮次、首个流式信号、工具成功/失败、授权、计划、检查点、token 与 Provider 实际上报的缓存量。
4. 点击“导出脱敏报告”，将 JSON 文件发送给维护者或 Codex 做外部复核。

导出是当前“AllyCode 与 Codex 连接”的安全实现：用户主动选择文件和发送对象，没有后台远程遥测，也不会自动上传项目内容。

## 确定性告警

- 运行失败或连续工具错误；
- 相同工具参数重复调用，提示潜在无进展循环；
- 复杂执行没有可见计划，或任务完成但计划仍未完成；
- 修改代码后没有成功的测试、构建、Lint 或类型检查证据；
- 同类权限请求过于频繁；
- 多轮输入 token 快速增长，提示上下文成本或漂移风险。

检测台分别呈现任务完成度、计划一致性、工具可靠性、证据完整性、记忆与恢复、安全与授权、成本与效率。只对有事件证据的维度评分；顶部数字是“已测维度平均值”，不是国际基准成绩，也不是单一上线判定。

## 隐私与证据边界

- 不采集或展示模型隐藏思维链，只记录首个文本、思考状态或工具信号的时间；
- 不在检测台展示文件内容和通用工具返回正文；命令工具只展示可解析的退出码；
- API key、Bearer token 和常见查询密钥在导出前再次脱敏；
- 检测台不自动联网、不上传遥测、不把密钥送入 renderer；
- 缓存指标只反映 Provider 实际上报，0 不等于“不支持缓存”；
- 规则告警不能替代需求验收、人工代码审查、SWE-bench/Terminal-Bench 或真实业务测试；语义偏航仍需用目标、产物和验收标准做外部评审。

## 复杂项目验收建议

测试全自动电商平台时，不要一次要求模型“做完全部商业系统”。先固定项目范围和验收集，将任务拆成商品、库存、订单、支付、客服、回访、运营自动化与安全合规等里程碑。每个里程碑要求计划、代码、自动测试、运行证据和未完成项。检测台用于发现循环、无验证写入、上下文膨胀和恢复断链；业务正确性由独立测试和人工验收决定。
